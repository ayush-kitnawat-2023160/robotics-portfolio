01 / THE BIG PICTURE

The problem & our solution.

An embedded-systems project to measure and monitor a model rocket’s flight from the ground.

THE REAL-WORLD PROBLEM

Why was this needed?

During flight and testing, a rocket cannot be connected to a laptop by a cable. The team needs live information about its altitude, orientation and system behavior to understand what is happening and investigate faults.

THE PROJECT GOAL

What did we set out to build?

Build an STM32-based onboard sensing and telemetry system, send flight measurements over LoRa, and display the readings through a Python ground station.

PRACTICAL VALUE

Why does it matter?

Makes flight data visible during experiments and available for review afterward. No verified radio range or flight reliability metric is claimed here.

⌖
Project context

Embedded microcontroller, onboard sensing, wireless telemetry and Python ground station.

04 / THE ENGINEERING

Challenges & what I did.

What made the project difficult, and the choices I made while working through it.

01 / EMBEDDED

Hardware delivers different sensor signals

THE PROBLEM

A flight controller needs to bring together multiple measurements at a useful update cadence.

MY APPROACH

Built STM32-side sensor integration and a consistent stream of altitude, orientation and flight data.

Evidence / boundary: Avionics and telemetry implementation described in the resume.

02 / LINK

The receiver is not next to the rocket

THE PROBLEM

A telemetry system must communicate over a wireless long-range channel instead of relying on a cable.

MY APPROACH

Selected LoRa for telemetry transport and built corresponding reception handling at the ground station.

Evidence / boundary: LoRa hardware and software integration.

03 / DIAGNOSTICS

Raw serial values are hard to interpret during testing

THE PROBLEM

Flight telemetry is more useful when operators can inspect trends while it arrives.

MY APPROACH

Implemented Python-based live monitoring and a post-flight analysis path rather than storing unstructured logs alone.

Evidence / boundary: Ground-station visualization and monitoring software.
