01 / THE BIG PICTURE

The problem & our solution.

We built avionics to collect flight measurements, handle noisy IMU readings, and send useful telemetry from a model rocket to a ground station.

THE REAL-WORLD PROBLEM

Why was this needed?

During flight and testing, a rocket cannot be connected to a laptop by a cable. Its onboard IMU readings can also be noisy and accumulate drift, making orientation estimates harder to trust. The team needed a way to process sensor data and monitor the rocket remotely.

THE PROJECT GOAL

What did we set out to build?

Integrate onboard sensors with an STM32, use Kalman-filter-based sensor fusion to reduce IMU estimation drift, transmit telemetry over LoRa, and visualize the measurements in a Python ground station.

PRACTICAL VALUE

Why does it matter?

Combines onboard sensing, state estimation and wireless monitoring in one embedded pipeline, making flight behavior easier to inspect. Drift reduction and radio performance are not presented as quantified results.

⌖
Project context

STM32 firmware, IMU and onboard sensors, Kalman filtering, LoRa telemetry and Python ground-station software.

03 / SYSTEM DESIGN

How it works.

01

Read sensors

Collect IMU and other flight-related sensor readings on the STM32.

02

Estimate & fuse

Apply Kalman filtering to combine sensor information and reduce noise and accumulated IMU drift in the estimated motion state.

03

Prepare telemetry

Package sensor readings and the estimated flight state into data suitable for transmission.

04

Transmit

Send telemetry packets from the rocket over LoRa to the ground receiver.

05

Visualize

Decode and display live values in a Python ground station for inspection and later analysis.

04 / THE ENGINEERING

Challenges & what I did.

What made the project difficult, and the choices I made while working through it.

01 / EMBEDDED

Bringing multiple sensors into one system

THE PROBLEM

Different onboard sensors produce different measurements that need to be collected and processed together.

MY APPROACH

Integrated the sensor readings with STM32 firmware to provide altitude, orientation and other flight-related data.

Evidence / boundary: An integrated onboard sensing path feeding the rest of the avionics system.

02 / SENSOR FUSION

IMU noise and drift affect the orientation estimate

THE PROBLEM

Using raw IMU measurements alone can produce noisy estimates; small errors accumulate when angular motion is integrated over time.

MY APPROACH

Worked on Kalman-filter-based sensor fusion to combine onboard measurements and correct the IMU-derived estimate, rather than relying on unfiltered data.

Evidence / boundary: A filtering and estimation stage added to the avionics workflow. No numerical drift-reduction benchmark is claimed.

03 / LINK

The receiver is not next to the rocket

THE PROBLEM

The rocket must send useful state information over a wireless link rather than relying on a cable.

MY APPROACH

Used LoRa to transmit telemetry and handled reception on the ground-station side.

Evidence / boundary: LoRa communication between the onboard system and ground receiver.

04 / DIAGNOSTICS

Raw readings are difficult to inspect during testing

THE PROBLEM

Sensor data is more useful when the team can see how the estimates and measurements change over time.

MY APPROACH

Built Python-based live monitoring and an analysis workflow for received telemetry.

Evidence / boundary: Ground-station visualization of flight-related measurements.
