Vision-guided robotic arm.

Taking an object detected by a camera and turning it into a reachable robot target.

01 / THE PROJECT

What was this about?

A camera knows where an object appears in its own coordinate frame; the arm needs a target in robot-base coordinates. This project connected visual detection, calibrated transforms and robot API commands in a vision-guided manipulation workflow.

⌖
Project context

xArm robotic hardware + camera calibration and ArUco-based observations.

02 / OWNERSHIP

What I actually worked on.

My responsibilities — distinguished from everything the wider team or research project may have explored.

01

Calibrated the camera and worked on estimating marker/object pose using OpenCV and ArUco fiducials.

02

Computed camera-to-robot frame transforms to express perceived object poses relative to the manipulator base.

03

Integrated estimated target poses with Python xArm API commands for end-effector positioning.

04

Participated in system tests aligning image-space observations with physical robot actions.

03 / SYSTEM DESIGN

How the pipeline fits together.

01

Observe

Capture the workspace and detect ArUco markers or target objects.

02

Recover a 3D pose from calibrated camera geometry and marker observations.

03

Transform

Apply camera-to-base extrinsic transforms to obtain the robot-frame target.

04

Act

Use the xArm Python API to move toward a validated target pose.

04 / THE ENGINEERING

The problems & how I approached them.

The interesting part isn't just a working screenshot; it's the decisions behind the implementation.

01 / FRAMES

Pixel coordinates are not robot coordinates

THE PROBLEM

A pose expressed in the camera optical frame cannot be sent directly to a manipulator expecting base-frame coordinates.

MY APPROACH

Calibrated camera geometry and implemented explicit homogeneous transformations from camera frame to robot base.

Evidence / boundary: The central implementation responsibility documented in the resume.

02 / RELIABILITY

Visual estimates jitter, but hardware needs stable targets

THE PROBLEM

Marker visibility, depth uncertainty and calibration error affect how confidently a position can be used.

MY APPROACH

Used pose estimation from known marker geometry and careful transformation checks before using target estimates in robot commands.

Evidence / boundary: Project demonstration shows the physical perception-to-action pipeline.

03 / INTEGRATION

Perception and actuation have different interfaces

THE PROBLEM

Computer vision returns detections and transforms; the arm controller needs feasible target poses and explicit motion commands.

MY APPROACH

Built the connection from estimated target pose to xArm API calls, keeping visual localization and actuation as separate stages.

Evidence / boundary: The demonstration and project code are linked below.
