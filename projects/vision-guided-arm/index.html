ROBOTICS / VISION-GUIDED SORTING

Vision-guided sorting robot.

Detecting tabletop objects, identifying visual attributes, and picking and placing them into bins with a real robotic arm.

01 / THE BIG PICTURE

The problem & our solution.

We built a camera-guided tabletop sorting system that detects objects, checks their visual attributes, and directs a robotic arm to pick them up and place them in the appropriate bins.

THE REAL-WORLD PROBLEM

Why was this needed?

Manual sorting is repetitive, and the objects on a table do not always stay in fixed positions. For a robot to sort them, it has to locate each object, recognize its color and whether it has a visual mark, translate that observation into robot coordinates, and execute a reliable grasp.

THE PROJECT GOAL

What did we set out to build?

Connect object detection and visual-attribute checks to an explicit sorting pipeline: calibrate the camera and workspace, map detected objects into robot coordinates, select a destination using defined rules, and perform top-down pick-and-place with a robotic arm.

PRACTICAL VALUE

Why does it matter?

The resulting pipeline connects perception with real robot actions. Instead of relying on fixed object positions, the arm uses the camera to find a target and move it to a designated bin. The recorded demo shows the real hardware in action.

⌖
Project context

UFactory xArm Lite6, Intel RealSense camera, AprilTag/ArUco workspace and bin references, YOLO object detection, color/mark checks, OpenCV mapping, and Python robot control.

03 / SYSTEM DESIGN

How it works.

01

Calibrate & map

Calibrate the camera and use AprilTag/ArUco reference markers to locate the tabletop workspace and sorting bins. Build the image-to-robot mapping.

02

Detect & classify

Detect tabletop blocks in the camera feed with YOLO. Identify their color and check for a visual mark using image-based rules.

03

Choose a bin

Use deterministic sorting rules to select a destination bin for a detected object, keeping classification separate from robot motion.

04

Convert coordinates

Map the object center and selected bin from image pixels into robot-frame XY coordinates using the calibrated workspace homography.

05

Pick & place

Send xArm commands for a top-down approach, grasp, lift, move to the bin, release, and return. Handle arm-command errors with a safe recovery path.

04 / THE ENGINEERING

Challenges & what I did.

What made the project difficult, and the choices I made while working through it.

01 / CALIBRATION

A pixel location is not a grasp position

THE PROBLEM

The camera returns image coordinates, but the xArm needs target positions in its own workspace. Small mapping errors can lead to missed grasps.

MY APPROACH

Used camera calibration and reference markers to establish a workspace homography, converting object and bin positions from pixels to robot XY.

Implementation detail: The robot receives target coordinates computed from camera observations rather than hard-coded object locations.

02 / PERCEPTION

Finding the object is only half the task

THE PROBLEM

The sorting task involves both object location and visual attributes. The workspace also contains reference markers used for calibration.

MY APPROACH

Separated object detection, color recognition, visual-mark checks, and workspace-marker detection so each has a clear purpose in the pipeline.

Implementation detail: YOLO supplies block detections; image-based checks label color and mark presence; fiducial markers define the workspace and bins.

03 / HARDWARE INTEGRATION

Turning a detection into a safe pick-and-place sequence

THE PROBLEM

Even with a correct detection, the arm needs a sensible approach height, gripper timing, a bin target, and a way to respond to motion errors.

MY APPROACH

Connected calibrated coordinates to xArm motion and gripper commands using a top-down approach, lift, transfer, and release sequence with error recovery.

Implementation detail: The real-hardware video shows the perception-to-motion integration and the physical sorting workspace.
