EdgeFusion multi-camera tracking.

Running detection near cameras and transmitting useful signals instead of every video frame.

01 / THE PROJECT

What was this about?

Streaming every camera frame to a single server wastes network bandwidth and can add latency. EdgeFusion explores a more practical architecture: run fast object detection on Jetson nodes, transfer cropped detections and metadata, then perform cross-camera tracking centrally.

⌖
Project context

NVIDIA Jetson Orin Nano edge devices, multi-camera experiments.

04 / THE ENGINEERING

The problems & how I approached them.

The interesting part isn't just a working screenshot; it's the decisions behind the implementation.

01 / COMPUTE

Full neural inference on an edge device is expensive

THE PROBLEM

Jetson resource limits constrain the number of camera streams and frame rate.

MY APPROACH

Applied TensorRT FP16/INT8 optimization to YOLO detectors and measured throughput instead of assuming desktop performance.

Evidence / boundary: 20 FPS single-camera and 7–8 FPS multi-stream as reported in the resume.

02 / BANDWIDTH

Multi-camera video is a costly thing to move

THE PROBLEM

Shipping unfiltered full video over the network increases bandwidth demand.

MY APPROACH

Changed the architecture to transmit object crops and compact metadata via ZeroMQ, keeping heavier image processing near the camera.

Evidence / boundary: Distributed inference architecture implemented during IRAS HUB research.

03 / ASSOCIATION

One object appears under different cameras

THE PROBLEM

Individual detections do not automatically maintain a consistent identity across time or camera boundaries.

MY APPROACH

Used centralized DeepSORT-based tracking and cross-camera association to maintain object tracks beyond a single frame.

Evidence / boundary: Research pipeline implementation; identity accuracy is not claimed without an evaluation report.
